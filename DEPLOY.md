# Как выложить агента chiptune-marketer в интернет

Эта инструкция для человека, который **не программист**.  
Цель: агент начнёт работать на серверах Cursor (не только на вашем компьютере), чтобы по расписанию собирать контент и (после настройки) создавать видео через HeyGen.

Делайте шаги **по порядку**. Не пропускайте шаг, даже если кажется «очевидным».

---

## Что вы получите в конце

1. Агент будет жить по адресу вроде панели **Deployed Agents** в Cursor.
2. Вы сможете написать ему сообщение и получить посты + сценарий видео.
3. По будням он сам будет запускать дневной пакет контента.
4. Если вы добавите ключи HeyGen — он сможет заказывать AI-видео с аватаром.

---

## Что нужно заранее (чеклист)

Отметьте у себя на бумаге:

- [ ] Компьютер с интернетом (Windows, Mac или Linux).
- [ ] Аккаунт на [cursor.com](https://cursor.com) (тот же, через который вы уже общаетесь с агентами).
- [ ] Аккаунт на [github.com](https://github.com) (бесплатного достаточно).
- [ ] На тарифе Cursor доступен **Deployed Agents / Agent SDK hosting** (если `deploy` напишет про entitlement / billing — нужен подходящий план или админ команды).
- [ ] Позже (не обязательно в первый день): аккаунт [HeyGen](https://www.heygen.com) и API-ключ.

**Важно про Privacy Mode:**  
В настройках Cursor режим **Privacy Mode (Legacy)** блокирует хостинг. Нужен обычный **Privacy Mode** (не Legacy). Если не уверены — Settings → Privacy в Cursor Dashboard.

---

## Словарь (коротко)

| Слово | Простыми словами |
| --- | --- |
| **Агент** | Программа-помощник, которая пишет тексты и вызывает сервисы |
| **Репозиторий (repo)** | Папка проекта на GitHub, как «облачный сейф с кодом» |
| **Commit** | Сохранённая версия файлов («снимок») |
| **Push** | Отправка снимка с компьютера на GitHub |
| **Deploy** | Запуск этой версии на серверах Cursor |
| **Slug** | Короткое имя агента в системе: у нас `chiptune-marketer` |
| **Секрет (secret)** | Пароль/ключ, который хранится у Cursor и не светится в коде |
| **Alias token** | Одноразовый «мастер-ключ» доступа к агенту после первого deploy — его надо сохранить у себя |

# Часть 0. Откройте папку проекта

Проект лежит здесь:

```text
/agent/chiptune-marketer
```

Если вы работаете на своём домашнем компьютере — скопируйте туда всю папку `chiptune-marketer` (или клонируйте репозиторий с GitHub, когда он появится).

Откройте **терминал** (командную строку):

- **Mac:** Программы → Утилиты → Терминал  
- **Windows:** установите [Windows Terminal](https://aka.ms/terminal) или используйте PowerShell  
- **Linux:** обычный Terminal

Перейдите в папку проекта:

```bash
cd /agent/chiptune-marketer
```

(На своём ПК путь будет другим — тот, куда вы положили папку.)

Проверка: команда ниже должна показать файлы `package.json`, папки `bot` и `evals`:

```bash
ls
```

# Часть 1. Установите Node.js (если ещё нет)

Agent SDK работает только через **Node.js** (не Bun).

1. Откройте https://nodejs.org  
2. Скачайте LTS-версию **22** или новее.  
3. Установите как обычную программу.  
4. В терминале проверьте:

```bash
node -v
```

Должно быть что-то вроде `v22.x.x` или выше. Если команда «не найдена» — Node не установился; перезапустите терминал и повторите.

---

# Часть 2. Войдите в Cursor из терминала

В папке проекта выполните:

```bash
npx --yes @grok/agent-sdk@0.5.0 login
```

1. Команда откроет браузер или покажет ссылку.  
2. Войдите в свой аккаунт Cursor.  
3. Разрешите доступ.  
4. Вернитесь в терминал — должно появиться подтверждение входа.

Проверка:

```bash
npx --yes @grok/agent-sdk@0.5.0 whoami
```

Должны увидеть свой аккаунт (email / имя), а не текст «Not signed in».

# Часть 3. Положите проект на GitHub

Cursor **не загружает файлы с вашего диска напрямую**.  
Он берёт код **только из GitHub** (из уже отправленной версии).

## 3.1. Создайте пустой репозиторий на GitHub

1. Откройте https://github.com/new  
2. **Repository name:** например `chiptune-marketer`  
3. Выберите **Private** (рекомендуется).  
4. **Не** ставьте галочки «Add README», «Add .gitignore», «Add license» — репозиторий должен быть пустым.  
5. Нажмите **Create repository**.  
6. Скопируйте HTTPS-адрес. Он выглядит так:

```text
https://github.com/ВАШ_ЛОГИН/chiptune-marketer.git
```

## 3.2. Подключите локальную папку к GitHub

В терминале, внутри `chiptune-marketer`:

```bash
git status
```

Если git уже инициализирован (как в облачной сборке), вы увидите ветку  
`cursor/chiptune-marketer-1ae7`.

Добавьте remote (подставьте **свой** URL):

```bash
git remote add origin https://github.com/ВАШ_ЛОГИН/chiptune-marketer.git
```

Если команда скажет, что `origin` уже есть:

```bash
git remote -v
git remote set-url origin https://github.com/ВАШ_ЛОГИН/chiptune-marketer.git
```

## 3.3. Убедитесь, что всё сохранено в commit

```bash
git status
```

Если есть изменённые файлы (не пусто):

```bash
git add -A
git commit -m "Prepare chiptune-marketer for deploy"
```

Если написано `nothing to commit, working tree clean` — всё уже сохранено, идите дальше.

## 3.4. Отправьте код на GitHub (push)

```bash
git push -u origin HEAD
```

GitHub может попросить войти:

- лучше использовать **Personal Access Token** или вход через браузер/GitHub CLI;
- обычный пароль от сайта GitHub для `git push` часто **не** подходит.

Проверка: откройте страницу репозитория в браузере — должны увидеть папки `bot`, `evals`, файл `package.json`.

**Без успешного push деплой не сработает.** Незакоммиченные и неотправлённые правки на сервер не попадут.

# Часть 4. Проверьте проект перед выкладкой

Всё ещё в папке проекта:

```bash
npx --yes @grok/agent-sdk@0.5.0 validate --dir .
```

Ожидание: команда заканчивается без ошибок (OK).

Дополнительно (по желанию):

```bash
npx tsc --noEmit -p .
```

Тоже должно пройти без ошибок.

Если `validate` ругается — **не** делайте deploy. Скопируйте текст ошибки и пришлите помощнику/в чат Cursor.

# Часть 5. «Сухой прогон» deploy (ничего не публикует)

Это репетиция: Cursor покажет, *что* он собирается выложить, но **ничего не меняет**.

```bash
npx --yes @grok/agent-sdk@0.5.0 deploy --dir . --dry-run
```

Посмотрите в выводе:

- имя агента (**slug**): ожидайте `chiptune-marketer`;
- откуда берётся код (репозиторий GitHub);
- какой commit / ветка.

Если slug или repo выглядят чужими — остановитесь и сверьте `git remote -v` и папку `--dir`.

# Часть 6. Настоящий deploy (публикация)

## 6.1. Запуск

Делайте это **в своём терминале** (не просите облачного бота сделать первый deploy за вас):  
при первом успешном deploy один раз покажут **alias token**. Его нельзя светить в чатах.

```bash
npx --yes @grok/agent-sdk@0.5.0 deploy --dir .
```

Команда может работать несколько минут. Дождитесь конца.

Успех = статус вроде **running** (агент запущен), не `pending` / `failed`.

## 6.2. Сохраните alias token

Если терминал показал токен / alias URL:

1. Откройте менеджер паролей (Bitwarden, 1Password, менеджер браузера) или надёжный файл только для вас.  
2. Сохраните:
   - **Alias URL** (адрес агента),
   - **Alias token** (секретный ключ).  
3. Права на файл, если сохраняете в файл на Linux/Mac:

```bash
chmod 600 ~/chiptune-marketer-alias.txt
```

Если токен потеряли позже:

```bash
npx --yes @grok/agent-sdk@0.5.0 deployment rotate-token chiptune-marketer
```

Старый токен перестанет работать; новый снова сохраните у себя.

## 6.3. Откройте панель

Откройте в браузере:

https://cursor.com/dashboard/deployed-agents

Там должен появиться агент **chiptune-marketer**.

Проверка статуса из терминала:

```bash
npx --yes @grok/agent-sdk@0.5.0 deployment get chiptune-marketer
```

Нужен статус **running**. Если `failed` — смотрите `lastError` и не повторяйте deploy вслепую.

# Часть 7. Секреты HeyGen (для AI-видео)

Без этой части агент **всё равно** пишет посты и сценарии.  
С этой частью он сможет **заказывать видео** в HeyGen.

## 7.1. Что взять в HeyGen

1. Зарегистрируйтесь / войдите на https://www.heygen.com  
2. Создайте **аватар** (фото-аватар или готовый). Скопируйте **Avatar ID**.  
3. Выберите голос с нормальным **русским** (или подходящим акцентом). Скопируйте **Voice ID**.  
4. В разделе API создайте **API Key**.

Никому не присылайте API Key в Telegram/чат.

## 7.2. Запишите секреты в Cursor

Имена секретов уже объявлены в коде (`HEYGEN_API_KEY`, `HEYGEN_AVATAR_ID`, `HEYGEN_VOICE_ID`).

В терминале (по одному имени; значение спросит скрытым вводом):

```bash
npx --yes @grok/agent-sdk@0.5.0 secret set chiptune-marketer HEYGEN_API_KEY
```

Вставьте ключ, Enter.

```bash
npx --yes @grok/agent-sdk@0.5.0 secret set chiptune-marketer HEYGEN_AVATAR_ID
```

```bash
npx --yes @grok/agent-sdk@0.5.0 secret set chiptune-marketer HEYGEN_VOICE_ID
```

Проверка имён (значения не показывает — так и должно быть):

```bash
npx --yes @grok/agent-sdk@0.5.0 secret list chiptune-marketer
```

Передеплоить из‑за новых значений секретов **обычно не нужно** — следующий запрос агента уже увидит их.

# Часть 8. Первая проверка «жив ли агент»

Отправьте тестовое сообщение на хостинг:

```bash
npx --yes @grok/agent-sdk@0.5.0 session create --slug chiptune-marketer --message "Собери короткий дневной контент-пакет на сегодня" --wait
```

Флаг `--wait` важен: без него команда может завершиться до появления ответа.

Что ожидать в ответе:

- несколько постов на русском;
- сценарий короткого видео;
- `packId` сохранённого пакета;
- либо статус HeyGen, либо список «что ещё настроить».

Посмотреть сессии:

```bash
npx --yes @grok/agent-sdk@0.5.0 session list --prod --slug chiptune-marketer
```

Логи (если что-то странное):

```bash
npx --yes @grok/agent-sdk@0.5.0 logs --prod --slug chiptune-marketer --once
```

# Часть 9. Расписание (ежедневный контент)

В проекте уже есть расписание `daily-content`:

- cron: `0 7 * * 1-6`
- это **07:00 UTC**, понедельник–суббота  
- зимой в Германии (Europe/Berlin) это примерно **08:00**

На хостинге расписание запускается само, когда deployment в статусе **running**.

Локально в режиме разработки (`dev`) расписание **само не тикает** — это нормально.

# Часть 10. Как обновлять агента после правок

Каждый раз, когда меняете код:

1. Сохраните файлы.  
2. В папке проекта:

```bash
git add -A
git commit -m "Опишите коротко, что изменили"
git push
```

3. Снова выложите:

```bash
npx --yes @grok/agent-sdk@0.5.0 validate --dir .
npx --yes @grok/agent-sdk@0.5.0 deploy --dir . --dry-run
npx --yes @grok/agent-sdk@0.5.0 deploy --dir .
```

Помните: на сервер попадает только то, что уже в GitHub после `push`.

Сессии и сохранённые пакеты контента (`kv` / files) при redeploy обычно **сохраняются**.  
Временные файлы на диске контейнера — нет.

# Часть 11. Частые проблемы

| Симптом | Что проверить |
| --- | --- |
| `Not signed in` | Снова `agent-sdk login`, потом `whoami` |
| `Privacy Mode (Legacy)` | В Cursor Dashboard сменить Privacy Mode |
| Deploy не видит код / старая версия | Сделали ли `git push`? Смотрите commit на GitHub |
| `failed` после deploy | `deployment get chiptune-marketer` и текст ошибки |
| Нет видео HeyGen | Секреты через `secret list`; есть ли `api.heygen.com` в egress (уже в проекте) |
| `permission` / entitlement | Тариф / права команды на Deployed Agents |
| Потеряли alias token | `deployment rotate-token chiptune-marketer` |

# Часть 12. Чего эта инструкция пока НЕ делает

Чтобы ожидания были честными:

- агент **не публикует** сам в Instagram / TikTok / YouTube (пока нет подключений к этим API);
- агент **не крутит рекламу** в Ads Manager сам;
- вы (или следующий этап автоматизации) копируете готовые тексты/видео и публикуете вручную;
- для аватар-видео нужен оплаченный/доступный API HeyGen и созданный аватар.
